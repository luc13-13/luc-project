# 认证中心 & 鉴权网关架构改进方案

> 基于 Spring Boot 4.0.1 / Spring Security 7.0 / Spring Cloud 2025.1.0  
> 编写日期：2026-03-06

---

## 一、背景

项目当前使用 Spring Boot 4.0.1，对应 Spring Security 7.0.x。Spring Authorization Server 已合并进 Spring Security 7.0。本文档针对 `authorization-server`、`authorization-gateway` 以及 `framework-security` 三个模块，提出基于最新框架版本的改进方案，前提条件为**继续使用 Redis 存储 SecurityContext**。

### 涉及模块

| 模块 | 路径 | 说明 |
|------|------|------|
| framework-security-core | `luc-framework/framework-security/framework-security-core` | 安全核心抽象 |
| framework-security-authorization-server | `luc-framework/framework-security/framework-security-authorization-server` | 认证服务器自动配置 |
| authorization-server | `authorization-server` | 认证服务 |
| authorization-gateway | `authorization-gateway` | 鉴权网关 |

## 三、高优先级改进详情

### 3.1 `RedisSecurityContextRepository` 迁移至 `loadDeferredContext`

#### 问题

`RedisSecurityContextRepository` 实现了已被 Spring Security 7.0 废弃的 `loadContext(HttpRequestResponseHolder)` 方法。该方法将在后续版本中被移除。新的 `loadDeferredContext(HttpServletRequest)` 支持延迟加载，白名单路径的请求不会触发 Redis 查询。

#### 涉及文件

```
luc-framework/framework-security/framework-security-authorization-server/
  src/main/java/com/lc/framework/security/auth/server/authentication/
    RedisSecurityContextRepository.java
```

#### 实施步骤

1. 删除 `loadContext(HttpRequestResponseHolder)` 方法
2. 新增 `loadDeferredContext(HttpServletRequest)` 方法，返回 `DeferredSecurityContext`
3. `containsContext` 方法保持不变
4. `saveContext` 方法保持不变

#### 目标代码

```java
@Override
public DeferredSecurityContext loadDeferredContext(HttpServletRequest request) {
    return new DeferredSecurityContext() {
        private SecurityContext context;
        private boolean isGenerated;

        @Override
        public SecurityContext get() {
            if (context == null) {
                String token = extractToken(request);
                if (StringUtils.hasText(token)) {
                    context = loadContextFromRedis(token);
                }
                if (context == null) {
                    context = SecurityContextHolder.createEmptyContext();
                    isGenerated = true;
                }
            }
            return context;
        }

        @Override
        public boolean isGenerated() {
            get();
            return isGenerated;
        }
    };
}
```

#### 验证方式

- 使用 `luc_auth_token` 请求已认证接口，确认 SecurityContext 正确加载
- 请求白名单路径，确认不触发 Redis 查询（可通过 Redis MONITOR 命令观察）
- 无 token 请求，确认返回空 context

### 3.2 网关 `RedisServerSecurityContextRepository` 空值校验 + Cookie 支持

#### 问题

1. 当请求头中没有 `luc_auth_token` 时，`key` 为 null，Redis 会查询 `spring:security:context:null`
2. 不支持从 Cookie 中读取 token（auth-server 的 `LoginSuccessHandler` 会同时设置 Cookie）
3. 不支持 Bearer 前缀剥离（auth-server 的 `RedisSecurityContextRepository` 支持）

#### 涉及文件

```
authorization-gateway/
  src/main/java/com/lc/authorization/gateway/security/
    RedisServerSecurityContextRepository.java
```

#### 实施步骤

1. 新增 `extractToken(ServerHttpRequest)` 私有方法，支持 Header / Cookie / Bearer 前缀
2. `load()` 方法中先校验 token 非空再查询 Redis
3. 删除类内重复的常量定义，统一引用 `OAuth2ParameterConstants`

#### 目标代码

```java
import static com.lc.framework.security.core.constants.OAuth2ParameterConstants.*;

@Slf4j
public class RedisServerSecurityContextRepository implements ServerSecurityContextRepository {

    private final ReactiveRedisTemplate<String, Object> reactiveRedisTemplate;
    private final Duration timeout;

    public RedisServerSecurityContextRepository(
            ReactiveRedisTemplate<String, Object> reactiveRedisTemplate,
            Duration timeout) {
        this.reactiveRedisTemplate = reactiveRedisTemplate;
        this.timeout = timeout;
    }

    @Override
    public Mono<Void> save(ServerWebExchange exchange, SecurityContext context) {
        return Mono.empty();
    }

    @Override
    public Mono<SecurityContext> load(ServerWebExchange exchange) {
        String token = extractToken(exchange.getRequest());
        if (!StringUtils.hasText(token)) {
            return Mono.empty();
        }
        String redisKey = SECURITY_CONTEXT_PREFIX + token;
        return reactiveRedisTemplate.opsForValue().get(redisKey)
                .filter(SecurityContext.class::isInstance)
                .cast(SecurityContext.class)
                .flatMap(ctx -> reactiveRedisTemplate
                        .expire(redisKey, timeout)
                        .thenReturn(ctx));
    }

    private String extractToken(ServerHttpRequest request) {
        String token = request.getHeaders().getFirst(AUTH_KEY);
        if (StringUtils.hasText(token) && token.startsWith(BEARER_TOKEN_PREFIX)) {
            return token.substring(BEARER_TOKEN_PREFIX.length());
        }
        if (!StringUtils.hasText(token)) {
            HttpCookie cookie = request.getCookies().getFirst(AUTH_KEY);
            if (cookie != null) {
                token = cookie.getValue();
            }
        }
        return token;
    }
}
```

#### 验证方式

- 无 token 请求白名单路径 → 不触发 Redis 查询
- Header 方式传递 `luc_auth_token` → 正常加载
- Cookie 方式传递 `luc_auth_token` → 正常加载
- Header 带 `Bearer ` 前缀 → 正确剥离后查询

### 3.3 RSA 签名密钥持久化

#### 问题

`JwtConfiguration.generateRsaKey()` 在每次应用启动时重新生成 RSA 密钥对，导致：
- 重启后所有已签发 JWT 失效
- 多实例部署时各节点密钥不一致
- 网关缓存的 JWK Set 无法验证旧 token

#### 涉及文件

```
luc-framework/framework-security/framework-security-authorization-server/
  src/main/java/com/lc/framework/security/auth/server/jwt/
    JwtConfiguration.java

luc-framework/framework-security/framework-security-core/
  src/main/java/com/lc/framework/security/core/properties/
    SysSecurityProperties.java
```

#### 实施步骤

1. 在 `SysSecurityProperties` 中新增 JWT 密钥配置项：

```java
/**
 * JWT RSA 公钥文件路径（classpath 或文件系统路径）
 */
private String jwtPublicKeyLocation;

/**
 * JWT RSA 私钥文件路径
 */
private String jwtPrivateKeyLocation;

/**
 * JWT 密钥 ID，用于密钥轮转
 */
private String jwtKeyId = "luc-auth-key-1";
```

2. 修改 `JwtConfiguration`，优先从配置加载密钥，仅开发环境 fallback 到自动生成：

```java
@Bean
public JWKSource<SecurityContext> jwkSource(SysSecurityProperties properties) {
    RSAKey rsaKey;
    if (StringUtils.hasText(properties.getJwtPublicKeyLocation())
            && StringUtils.hasText(properties.getJwtPrivateKeyLocation())) {
        RSAPublicKey publicKey = loadPublicKey(properties.getJwtPublicKeyLocation());
        RSAPrivateKey privateKey = loadPrivateKey(properties.getJwtPrivateKeyLocation());
        rsaKey = new RSAKey.Builder(publicKey)
                .privateKey(privateKey)
                .keyID(properties.getJwtKeyId())
                .build();
        log.info("使用持久化 RSA 密钥，keyId: {}", properties.getJwtKeyId());
    } else {
        log.warn("未配置 JWT 密钥路径，使用随机生成密钥（仅适用于开发环境）");
        KeyPair keyPair = generateRsaKey();
        rsaKey = new RSAKey.Builder((RSAPublicKey) keyPair.getPublic())
                .privateKey((RSAPrivateKey) keyPair.getPrivate())
                .keyID(UUID.randomUUID().toString())
                .build();
    }
    return new ImmutableJWKSet<>(new JWKSet(rsaKey));
}
```

3. 生成密钥对文件并加入 `.gitignore`：

```bash
# 生成 RSA 密钥对
openssl genrsa -out jwt-private.pem 2048
openssl rsa -in jwt-private.pem -pubout -out jwt-public.pem
```

4. 配置文件中指定路径：

```yaml
sys:
  security:
    jwt-public-key-location: classpath:keys/jwt-public.pem
    jwt-private-key-location: classpath:keys/jwt-private.pem
    jwt-key-id: luc-auth-key-v1
```

#### 验证方式

- 启动 auth-server，签发 JWT
- 重启 auth-server，使用之前签发的 JWT 访问网关 → 验证通过
- 部署两个 auth-server 实例，两个实例签发的 JWT 在网关均可验证

### 3.4 网关统一传递用户信息

#### 问题

`JwtAuthenticationGlobalFilter` 仅处理 `JwtAuthenticationToken`。通过 Redis `luc_auth_token` 认证的请求（`UsernamePasswordAuthenticationToken`、`SmsAuthenticationToken`）不会向下游传递 `X-User-Id` / `X-User-Name` / `X-User-Authorities`，导致下游业务服务无法获取用户身份。

#### 涉及文件

```
authorization-gateway/
  src/main/java/com/lc/authorization/gateway/filter/
    JwtAuthenticationGlobalFilter.java
```

#### 实施步骤

1. 重命名为 `AuthenticationGlobalFilter`（可选，更准确）
2. 扩展 `filter()` 方法，针对不同 Authentication 类型提取用户信息：

```java
@Override
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
    return ReactiveSecurityContextHolder.getContext()
            .map(SecurityContext::getAuthentication)
            .filter(auth -> auth != null && auth.isAuthenticated())
            .map(auth -> {
                ServerHttpRequest.Builder requestBuilder = exchange.getRequest().mutate();

                if (auth instanceof JwtAuthenticationToken jwtAuth) {
                    Jwt jwt = jwtAuth.getToken();
                    addHeaderIfPresent(requestBuilder, USER_ID_HEADER, extractUserId(jwt));
                    addHeaderIfPresent(requestBuilder, USERNAME_HEADER, extractUsername(jwt));
                    addHeaderIfPresent(requestBuilder, USER_AUTHORITIES_HEADER,
                            extractAuthorities(jwtAuth));
                } else if (auth.getPrincipal() instanceof LoginUserDetail userDetail) {
                    addHeaderIfPresent(requestBuilder, USER_ID_HEADER, userDetail.getId());
                    addHeaderIfPresent(requestBuilder, USERNAME_HEADER, userDetail.getUsername());
                    addHeaderIfPresent(requestBuilder, USER_AUTHORITIES_HEADER,
                            userDetail.getAuthorities().stream()
                                    .map(GrantedAuthority::getAuthority)
                                    .collect(Collectors.joining(",")));
                }

                return exchange.mutate().request(requestBuilder.build()).build();
            })
            .defaultIfEmpty(exchange)
            .flatMap(chain::filter);
}

private void addHeaderIfPresent(ServerHttpRequest.Builder builder,
                                 String name, String value) {
    if (StringUtils.hasText(value)) {
        builder.header(name, value);
    }
}
```

#### 验证方式

- 使用 `luc_auth_token` 认证 → 下游服务收到 `X-User-Id`、`X-User-Name`、`X-User-Authorities`
- 使用 Bearer JWT 认证 → 下游服务同样收到上述 headers
- 未认证请求 → 不附加 headers

### 3.5 登出时清理 Redis SecurityContext

#### 问题

- `AuthController.logout()` 方法体为空
- `SecurityAutoConfiguration` 中 logout 配置仅清理 Cookie 和 HttpSession
- Redis 中的 SecurityContext 不会被清除，token 在 TTL 过期前仍可用于认证

#### 涉及文件

```
luc-framework/framework-security/framework-security-authorization-server/
  src/main/java/com/lc/framework/security/auth/server/authentication/
    新增: RedisLogoutHandler.java
  src/main/java/com/lc/framework/security/auth/server/authentication/
    LucAuthenticationConfiguration.java
  src/main/java/com/lc/framework/security/auth/server/
    SecurityAutoConfiguration.java

authorization-server/
  src/main/java/com/lc/auth/server/web/
    AuthController.java （删除空的 logout 方法，由 Security Filter 处理）
```

#### 实施步骤

1. 新建 `RedisLogoutHandler`：

```java
package com.lc.framework.security.auth.server.authentication;

import jakarta.servlet.http.Cookie;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.AllArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.security.core.Authentication;
import org.springframework.security.web.authentication.logout.LogoutHandler;
import org.springframework.util.StringUtils;
import org.springframework.web.util.WebUtils;

import static com.lc.framework.security.core.constants.OAuth2ParameterConstants.*;

@Slf4j
@AllArgsConstructor
public class RedisLogoutHandler implements LogoutHandler {

    private final RedisTemplate<String, Object> redisTemplate;

    @Override
    public void logout(HttpServletRequest request, HttpServletResponse response,
                       Authentication authentication) {
        String token = extractToken(request);
        if (StringUtils.hasText(token)) {
            String key = SECURITY_CONTEXT_PREFIX + token;
            Boolean deleted = redisTemplate.delete(key);
            log.info("登出清理 Redis SecurityContext, key: {}, deleted: {}", key, deleted);
        }
    }

    private String extractToken(HttpServletRequest request) {
        String token = request.getHeader(AUTH_KEY);
        if (StringUtils.hasText(token) && token.startsWith(BEARER_TOKEN_PREFIX)) {
            return token.substring(BEARER_TOKEN_PREFIX.length());
        }
        if (!StringUtils.hasText(token)) {
            Cookie cookie = WebUtils.getCookie(request, AUTH_KEY);
            if (cookie != null) {
                token = cookie.getValue();
            }
        }
        return token;
    }
}
```

2. 在 `LucAuthenticationConfiguration` 中注册 Bean：

```java
@Bean
@ConditionalOnClass(RedisTemplate.class)
@ConditionalOnProperty(prefix = SysSecurityProperties.PREFIX,
        name = "enable-redis", havingValue = "true")
public RedisLogoutHandler redisLogoutHandler(RedisTemplate<String, Object> redisTemplate) {
    return new RedisLogoutHandler(redisTemplate);
}
```

3. 在 `SecurityAutoConfiguration` 的 logout 配置中注入：

```java
// 方法参数增加
ObjectProvider<RedisLogoutHandler> redisLogoutHandlerProvider

// logout 配置中添加
.logout(logout -> {
    logout.logoutUrl(loginProperties.getLogoutUrl())
          .logoutSuccessUrl(loginProperties.getLogoutSuccessUrl())
          .addLogoutHandler(
              new CookieClearingLogoutHandler(AUTH_KEY, JSESSIONID, XSRF_TOKEN))
          .invalidateHttpSession(true)
          .permitAll();
    redisLogoutHandlerProvider.ifAvailable(logout::addLogoutHandler);
})
```

4. 删除 `AuthController.logout()` 空方法（由 Spring Security 的 LogoutFilter 统一处理）。

#### 验证方式

- 登录获取 `luc_auth_token` → 用该 token 访问受保护资源 → 成功
- 调用 `/logout` → 再用同一 token 访问受保护资源 → 401
- Redis 中确认对应 key 已被删除

### 4.8 SMS 验证码安全加固

#### 问题

1. `SmsCodeService` 使用 `java.util.Random` 生成验证码，可被预测
2. 无发送频率限制，存在短信轰炸风险

#### 实施步骤

1. 将 `Random` 替换为 `SecureRandom`：

```java
private static final SecureRandom SECURE_RANDOM = new SecureRandom();

private String generateCode() {
    StringBuilder code = new StringBuilder(CODE_LENGTH);
    for (int i = 0; i < CODE_LENGTH; i++) {
        code.append(SECURE_RANDOM.nextInt(10));
    }
    return code.toString();
}
```

2. 新增发送限流逻辑：

```java
private static final String SMS_RATE_LIMIT_PREFIX = "sms:rate:";
private static final int RATE_LIMIT_SECONDS = 60;

public String generateAndStoreCode(String phone) {
    String rateLimitKey = SMS_RATE_LIMIT_PREFIX + phone;
    if (Boolean.TRUE.equals(redisTemplate.hasKey(rateLimitKey))) {
        throw new BizException("发送过于频繁，请" + RATE_LIMIT_SECONDS + "秒后重试");
    }

    String code = generateCode();
    String key = SMS_CODE_PREFIX + phone;
    redisTemplate.opsForValue().set(key, code, CODE_EXPIRE_MINUTES, TimeUnit.MINUTES);
    redisTemplate.opsForValue().set(rateLimitKey, "1", RATE_LIMIT_SECONDS, TimeUnit.SECONDS);

    log.info("为手机号 {} 生成验证码", phone);
    return code;
}
```

```
luc-framework/framework-security/framework-security-authorization-server/
  src/main/java/com/lc/framework/security/auth/server/authentication/extension/sms/
    SmsCodeService.java
```

### 4.9 网关 Redis TTL 刷新

#### 问题

网关 `RedisServerSecurityContextRepository.load()` 读取 SecurityContext 后不刷新 TTL。auth-server 侧的 `RedisSecurityContextRepository` 会刷新 TTL。活跃用户仅通过网关访问时会话可能超时。

#### 实施步骤

已包含在 3.2 的目标代码中：

```java
.flatMap(ctx -> reactiveRedisTemplate
        .expire(redisKey, timeout)
        .thenReturn(ctx));
```

需要在 `SecurityConfiguration` 中将 timeout 参数传入 `RedisServerSecurityContextRepository` 构造函数。从 `GatewaySecurityProperties` 或 `SysSecurityProperties` 读取。

### 4.10 Token 生成安全加固

#### 问题

当前 token 生成方式包含 `System.currentTimeMillis()`，泄露服务器时间。

#### 实施步骤

```java
private String generateToken() {
    byte[] bytes = new byte[32];
    new SecureRandom().nextBytes(bytes);
    return Base64.getUrlEncoder().withoutPadding().encodeToString(bytes);
}
```

## 五、低优先级改进详情

### 5.13 利用 Authentication.Builder

Spring Security 7.0 引入了 `Authentication.Builder`，可在 `SmsAuthenticationProvider` 中简化认证对象构造。当前的 `SmsAuthenticationToken` 实现已经足够清晰，此项为可选优化。

### 5.14 MFA 框架适配评估

Spring Security 7.0 内置多因素认证支持。如果未来需要"密码 + 短信验证码"组合登录，可评估替换自定义的 `MultiTypeAuthenticationFilter`。当前单独的短信登录方式无需使用 MFA。

### 5.15 DelegatingPasswordEncoder 渐进升级

当前使用 BCrypt。Spring Security 7.0 新增 Password4j 支持（Argon2 等）。建议使用 `DelegatingPasswordEncoder`，已有 BCrypt 密码无需迁移，新用户自动使用最新算法：

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return PasswordEncoderFactories.createDelegatingPasswordEncoder();
}
```
